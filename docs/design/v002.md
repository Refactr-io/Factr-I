# v0.0.2 engine changes

General capability changes only: nothing is keyed to a dataset, host, marker or answer literal. Every guard reads
`FACTR_GUARD_<NAME>` (`0` turns it off, default on), so an ablation needs no rebuild.

| Switch | Guard |
| --- | --- |
| `FINAL_TEXT` | label-aware whole-reply final text |
| `VERIFY` | unexecuted-write check (tracker) |
| `SHORTFALL` | shortfall detector and iterate/decline nudge |
| `COMPUTE` | compute-before-final guard |
| `READ_FOOTER` | tabular footer line in `read` |
| `UNREAD` | unread-remainder guard |
| `FETCH_HINT` | webfetch/websearch failure text and 5xx archive fallback |
| `PENDING` | promoted/background check is pending, one wait nudge |
| `SKIPPED` | skipped-test follow-up |
| `ANSWER_SHAPE` | `answer_shape` attribute on the turn-end span |
| `BRIDGE` | `=0` registers the `factr` tool without a backend host |
| `STALE_BG` | note on an edit result when an older background task still runs |
| `SERVICE` | readiness recheck for an exited background server at a headless stop |
| `NOTOOLS` | `=0`: the shared tools-forbidden detector and every no-tools gating below are off (legacy phrase list) |
| `TEMPLATE` | `=0`: previous label detector, final_text rules and decline nudge texts, exactly (ablation) |
| `BG_DESC` | opt-in `=1`: newer `run_in_background` description plus the server hint in the start result (default: v0.0.1 text) |
| `ENV_INSTALLERS` | `=0`: drops the `installers` field from the environment line (default on) |
| `PROMPT_STDLIB` | `=0`: drops the missing-library / standard-library prompt rule (default on) |
| `PROMPT_BEST` | `=0`: v0.0.1 best-answer line (default on, a wash in the evidence) |

`ENV_INSTALLERS` and `PROMPT_STDLIB` are ON by default in 0.0.2 (round E): the measured benefit is on held-out data and
only a proxy, and they change no tool use under the no-tools line (the environment block is omitted for tasks that forbid
tools, and the library rule sits below the "user forbids tools overrides every rule" line). `BG_DESC` remains opt-in
(`=1`): no measured benefit. All are read once per process (tool schemas and the prompt are frozen per session). The
published-answers line is text, not switchable. Default first-request prefix: 4727 tokens (system 2600 + tool schemas
2127), 47 above round C (4680) and 45 above v0.0.1 (4682).

## Tasks that forbid tools

`factr_base::task_policy::forbids_tools(text)` is the one detector (first user message only). It normalises (lowercase,
curly apostrophes, `dont`, whitespace) and matches a negation (do not, don't, never, without, no, not allowed to, must
not, may not, cannot) then up to 4 filler words, an optional verb, up to 3 filler words and an object (tool, tool call,
tool use, code, python, shell, bash, terminal, calculator, repl, script); plus standalone by hand / in your head /
mentally / from memory and "tools are not allowed". A match followed within 2 words by changes, duplication, review,
directory, dir, folder, installed, or by `/`, is not a ban. When it fires (and `NOTOOLS` is not 0): the chain skips
verify, failed check, pending, service, unverified claim, measure, action, snippet, unread and compute; the question
nudge becomes "No user is available to answer. Give your answer now, without tools."; the shortfall and format nudges
stay; the 70% deadline reminder drops "verify"; the `<environment>` block is not attached. The system prompt carries
"If the user says not to use tools or code, answer directly; that overrides every rule below." at the top of the Coding
block, and the tool-first finishing line ends "unless the user forbids tools". A test checks every prompt line that
mentions tool, code or install is below the override or carries "unless".

## Rules shared by every nudge

- Headless only (the iterate, compute, verify and unread nudges), once per turn, never after 70% of the budget (the
  shortfall nudge after 50%). At most two chain nudges per turn, the second only after non-todo tool calls; the format
  nudge for a task label has its own allowance.
- No nudge text contains: final answer, restate, only, format, caveat, estimate, uncertain. A unit test asserts it over
  every nudge constant and the dynamic ones. The engine never rewrites, trims, appends to or concatenates the answer.
- Order: verify, failed check, pending check, unverified claim, measure, action, question, snippet, shortfall, compute,
  unread remainder, then the format nudge.

## Tracker

`StopNudge::observe_full` records the last input (read, webfetch, websearch), the last write (an edit tool on any path,
plus files changed by bash or the REPL, found by comparing a cwd mtime snapshot taken at turn start: depth 3, 5000
entries, VCS/dependency/venv directories skipped, off in `/` and home) and the last exec (bash/REPL run, or a read of a
written path). A run whose output says no tests ran (`Ran 0 tests`, `NO TESTS RAN`, `collected 0 items`,
`running 0 tests`, `0 passing`) is not an exec.

Bug fixed: edit-tool writes also move the cwd mtime, so the diff at the next bash run was read as a shell write stamped
with that run's sequence number, and `last_exec <= write` held (equal), so VERIFY fired on every edit-then-run task. Now
paths in the written list are excluded from the diff, the snapshot is refreshed after every bash/REPL run (the write is
stamped with that call's sequence number), and an exec must come strictly after the write. A bash run that itself writes
and runs a file in one command therefore still gets the check unless something runs later.

## Background guards (`bg_guard.rs`)

Stale note: after a successful edit tool call, the background manager's list is filtered to this session's running `bash`
tasks that started before the edit began; each gets the note once per turn. Service recheck: the turn loop asks the
manager for the status of the watched tasks before the text-only stop is judged and hands the exits to `StopNudge`.
A task is watched when bash returns `background: true` (not a promoted check command); it is flagged as a server by a
`bg` wait with `until` or a ready word (listening, ready, serving on, running on, ...) in `bg` output. Unflagged tasks count
only when they ran over 5 s and did not exit 0. A `bg` cancel, or a `bg` read of an unflagged task, removes it. Placed after
the pending-check branch in the chain; once per turn, headless, not late.

## Final text

`StopNudge::final_text(last)`: with a task label, the latest reply with a label line, whole; else the last reply; an
earlier nudged reply replaces the last only when the last is empty or at most 40 characters and not a bare number, a
shortfall or a question. Only the non-streaming loop assembles a final text; the streaming loop's answer is the last
assistant message and it only emits the turn-end span.

## Shortfall detector

A sentence of the last paragraph with a negation or shortfall word (could not, unable, cannot, not yet, below, short of,
fails to, not verified, not re-tested, ...) and an object word (target, threshold, requirement, test, verify, score,
expected, determine, find, answer, ...), or a self-sufficient phrase (not feasible, not installed, ...). Skipped when the
paragraph blames an unreadable input, when tests passed after the last write, and after half of the budget. Files written:
"try a different method, or install or implement the missing piece, re-run the check". No files: route-aware decline text.
Tools forbidden: no tool advice. A labelled corpus of 100 messages in the unit tests holds the precision on complete
messages at 0.9 or better.

## Compute and unread guards

The answer value is the label value (else the last non-empty line) with markdown, currency, `%`, thousands separators and
one trailing unit word removed; it must be `-?\d+(\.\d+)?`, with whole numbers 1000..2100 exempt. No bash/REPL run since
the last data-bearing call, or no tool at all, fires the guard once. The unread guard keys on webfetch's own window note
("showing head H + tail T of N chars") or a large-file overview; a later webfetch of that URL with `find` or `offset`, a read
of the spill path, or a fetch of another page clears it. No service-specific marker is parsed.

## Other

- bash: `run_in_background` no longer inherits the foreground `timeout`.
- webfetch: 5xx and connection errors after three attempts try the archive (when enabled), then say so plainly.
- `fake_model.py` (outside the repo, in the GUI test directory) accepts `SCRIPT:<file>` to replay a JSON step list.

## Answer template detection, final text and decline nudges (`TEMPLATE`)

Held-out dev traces showed three faults. (1) The label detector skipped a lowercase `word = <value>` template and took
a Title-case data heading in an example block, so the format nudge asked for the wrong label and a stub carrying it
replaced the correct earlier reply. (2) The decline nudges stopped asking for an answer. (3) With no label
recognised, a later prose reply displaced an earlier reply that carried the answer line.

- Detector: accepts `words = <placeholder>` and `words: <placeholder>` in any case; a placeholder opens with a
  bracket (`<`, `[`, `{`) followed by a letter, so `[[`, `[1`, `[-` and quoted data never count. The first template
  after a formatting verb wins and scanning stops. Verbs match on word boundaries (`endpoints` is not `end`). The
  prose label list is kept. Quoted capitalised labels without a placeholder still count.
- `final_text`: a stub (40 characters or fewer) carrying the label never displaces an earlier reply whose last line is
  a `label: value` or `label = value` line. With no label, a last reply that has no such line yields to the latest
  earlier reply that has one; an empty or stub last reply still falls back as before.
- Decline nudge: asks for the best answer in the requested form after the extra routes (routes are task-neutral);
  the no-tools nudge is now one sentence asking for that answer without tools. Shortfall phrase list unchanged.
- `FACTR_GUARD_TEMPLATE=0` restores the previous detector, `final_text` and nudge texts.
