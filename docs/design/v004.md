# v0.0.4: lighter session venv creation

Problem: the engine builds the session venv in a child process at start. `uv venv --seed` and `python -m venv`
(ensurepip) each install pip into the venv, which is the costly part: a visible child for ~2 s, sometimes ~8 s, and a
transient process-tree peak that benchmarks (which sample the whole tree) count against short tasks.

Change (`factr-base/src/python_env.rs`, `create_session_venv`):

- uv: `uv venv --system-site-packages --python <base> <dir>`. No pip in the venv; `uv pip install --python <venv python>`
  needs none.
- no uv: `<base> -m venv --system-site-packages --without-pip <dir>`. Before choosing, one
  `python -c 'import importlib.util;print(importlib.util.find_spec("pip") is not None)'` on the base interpreter; if the
  base has no pip, the old seeding (`ensurepip`) is used. Only run on this branch.
- The venv sees the base's site packages, so `<venv python> -m pip install` runs the system pip but installs into the
  venv (checked on CommandLineTools python 3.9.6, pip 21.2.4). The install hint is unchanged: `uv pip install --python
  <py> <pkg>` when uv exists, else `<py> -m pip install <pkg>`.
- A bare `pip install` in bash used to hit the venv's seeded `bin/pip`; without a seed it would reach the system pip.
  `write_pip_shims` writes `bin/pip` and `bin/pip3` (`exec "$(dirname "$0")/python" -m pip "$@"`) if absent.

Measured (macOS, CommandLineTools python 3.9.6, `rss_tree.py` / `measure.py` from dev/e2e-install/start-latency, 8 runs,
same-session comparison against dev binary 0.0.3-23ac298):

| variant | v0.0.3 tree peak MiB (med/min/max) | v0.0.4 | child window v0.0.3 | child window v0.0.4 |
|---|---|---|---|---|
| uv present | 70.9 / 68.8 / 71.2 | 53.8 / 53.2 / 65.8 | 1.9-2.2 s (2 of 8: ~8 s) | 0.06-0.16 s (one 1.5 s) |
| uv absent | 141.7 / 139.5 / 143.1 | 44.9 / 42.7 / 46.2 | ~1.9 s | 0.05-0.17 s |
| FACTR_GUARD_SESSION_VENV=0 | 28.5 | 28.6 | none | none |

Engine alone is ~28.6 MiB; ready time is ~0.14 s in all variants (unchanged). Task runs (bash + repl, 2 each): peak
tree 100-107 MiB -> 83 MiB with uv; guard=0 82-84 MiB.

E2E install-then-import (local dummy wheel, hint command, REPL next cell): uv and no-uv both install (exit 0) and import
(`dummyprobe-ok-42`). Wall time 4.3 s -> 1.8 s (uv), 2.3 s (no uv).
